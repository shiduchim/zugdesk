# V11 HANDOFF PRIORITY — SINGLE MODE WORKING PROTOTYPE

Build the functional Single Mode application first. Use the exact user-supplied Claude My Profile visuals as the protected source for the Profile screen, and use a coherent Claude minimalist visual language for the first integrated prototype. A second warm ChatGPT/ZivugMatch visual design for every page is a LATER REQUIREMENT ONLY; do not create or implement it in this handoff phase. Do not generate experimental Game or Neon palettes. Retain the supplied original appearance screenshots as future references. Shadchan Mode is excluded.

# What is in this document

- Shidduchim: Offers, In Progress, Ended; stages, dates, history and the outstanding Make Match flow.

- Add Person and Add Shadchan: approved intake architecture, detailed categories, contacts, attachments and source preservation.

- Home: approved notes, quick entry, follow-ups and history behavior.

- Desktop Contacts: the Outlook-style three-area layout and supplied original screenshot.

- Mobile Contacts: six user-selectable views, search, Sort, Filters, pinned people, optional folders and independent scrolling.

- My Profile: phone and desktop Profile, Short versions and private Notes reference layouts.

- People and Ideas / Offers: person-reading cards styled like My Profile, populated from Add Person fields.

- Appearance reference: keep the original ZivugMatch settings screenshots, including the existing Game and Neon choices. No assistant-created themes or theme demos are included.

# Design status and implementation boundary

- Approved baseline: Home, Shidduchim core, Add Person / Add Shadchan intake and the ability for the user to change Contacts views.

- Current design direction: Outlook-style desktop Contacts, My Profile screen references and profile-like saved-person cards.

- Still under review: default phone Contacts view, precise mobile dimensions and scroll behavior, joined or separate People and Ideas navigation and final visual defaults.

- Future implementation: one shared application data model and persistence across all pages. The companion HTML files are independent local design studies with fictional sample records.

# Companion files in the same ZIP

- My Profile.html — Profile, Short versions, private Notes and sharing demonstration.

- Shadchanim Offers.html — saved person cards, interest, sources, history and contact navigation.

- Contacts layouts.html — six selectable phone views with sort, filters, pinned and folder experiments.

- Theme screenshots.html — supplied screenshots only; no new theme implementation or interactive style picker.

- References folder — original Add Person v3.0 source and supplied screenshots.

Keep this document as the design source of truth. Do not replace the live site’s index.html with one of the standalone prototype files.
